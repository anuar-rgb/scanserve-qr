# ScanServe QR — История разработки проекта

> Дата последнего обновления: 25 мая 2026  
> Проект: Цифровое меню и POS-система для ресторана «Ас Тори»  
> URL продакшена: https://scanserve-qr-production.up.railway.app  
> Деплой: Railway (автодеплой при push в `master`)

---

## Стек технологий

| Слой | Технология |
|------|-----------|
| Фреймворк | Next.js 16 App Router (TypeScript) |
| БД и хостинг | Supabase (PostgreSQL + Storage + Realtime + Auth) |
| Стили (гостевое меню) | Inline `style` объекты, CSS переменные |
| Стили (админка) | Tailwind CSS + shadcn/ui компоненты |
| Шрифты | Montserrat (меню), Inter (админка) |
| Деплой | Railway (GitHub → auto-deploy) |
| Уведомления | Web Push (web-push библиотека, VAPID) |
| Печать | ESC/POS over TCP (LAN thermal printer) |
| Подпись | HTML5 Canvas API (pointer events) |

- Плавающий стеклянный хедер (`backdrop-filter: blur`)
- Flat design — никаких теней на карточках, только бордеры
- Footer «Powered by scanserve.qr»

### Корзина и оформление заказа
- Drawer корзины с группировкой по времени добавления

## Модуль 3 — Административная панель (`/admin`)

### Авторизация и роли (RBAC)

Три уровня доступа:

| Роль | Доступ |
|------|--------|
| `owner` | Полный доступ ко всем разделам |
| `manager` | Всё кроме финансового раздела владельца; может открывать/закрывать смены |
| `cashier` | POS терминал, история заказов |
| `waiter` | Только зал (свои столы), вызов официанта |
| `chef`, `bartender`, `sommelier` и ещё 9 ролей | Ограниченный доступ по роли |

- Авторизация через `staff_users` таблицу (bcrypt пароли)
- Cookie-сессия (`admin_session` = роль, `admin_user_id` = id)
- Страница `/admin/login` — форма входа

### Управление персоналом (`/admin/staff`)
- Список сотрудников (имя, логин, роль, статус)
- Добавить / редактировать / удалить сотрудника
- Сброс пароля
- 15 ролей: менеджер, кассир, официант, старший официант, повар, бармен, сомелье, хостес, раннер, курьер, кладовщик, бухгалтер, уборщик, швейцар

### Система смен
- Смена открывается менеджером/кассиром
- `ShiftGate` — блокирует доступ до открытия смены
- Официанты/повара не могут открыть смену — ждут менеджера
- Z-отчёт при закрытии смены
- Выручка по официанту за смену

### QR Check-in (отметка прихода)
- `CheckinGate` — официанты/повара сканируют QR у входа чтобы начать работу
- QR-токен хранится в `QR_CHECKIN_SECRET` env переменной
- `QrScannerModal` — камера прямо в браузере (jsQR / html5-qrcode)
- API `/api/admin/shift/checkin` — верифицирует токен и создаёт запись

### Каталог (`/admin/catalog`)
- Категории с фото (загрузка в Supabase Storage)
- Товары: название, описание, цена, фото, emoji
- Badge-метки: Новинка, Хит, Острое, кастомная метка с цветом
- Архивирование товаров (не удаляет, скрывает из меню)
- Переключатель «Доступно / Недоступно» в реальном времени
- Модификаторы (дополнения): группы с мин/макс количеством, привязка к конкретным блюдам
- Скидки: процентная скидка с датой действия

### Сторфронт (`/admin/main-screen`, `/admin/branding`, `/admin/banners`, `/admin/hero-slider`, `/admin/info-showcase`)
- Hero Slider: загрузка фото/видео, заголовок, описание, теги с цветами, порядок
- Брендинг: логотип, название ресторана, WhatsApp номер, акцент-цвет
- Баннеры: промо-изображения с ссылкой и активацией
- InfoShowcase: информационные карточки (emoji + текст) — часы, адрес, Wi-Fi и т.д.
- Рекомендации: блюда из каталога, отмечаются тегами Promo / New / Recommended

## Модуль 4 — POS Терминал (`/admin/hall`)

### Зал (Hall Plan)
- Интерактивная карта столов с live-статусом
- Стол: свободен / занят / предзаказ
- Realtime обновление через Supabase Channels (без перезагрузки)
- Автообновление каждые 30 секунд как fallback
- Добавить / редактировать / деактивировать стол
- Изменить стол для активного заказа
- Подтаблицы (sub-table): разделить стол на несколько заказов

### Панель заказа (TablePanel)
- Состав заказа с группировкой по времени добавления
- Добавить блюдо через POS-браузер меню (двухуровневый: категория → блюда)
- Модификаторы в заказе
- Заметки к каждой позиции
- Кнопки: Удалить позицию / Переложить на другой стол
- Антифрод система КОСЯК: вместо удаления — запись с причиной в `order_voids`
- Перевод позиций на другой стол (`order_transfers`)
- Оплата: модальное окно с выбором метода (наличные / карта-перевод / смешанная)
- Закрыть заказ = «Оплачено»

### Три вкладки POS
| Вкладка | Что |
|---------|-----|
| Dine-in | Карта столов + TablePanel |
| Takeaway | Очередь самовывоза + OrderSlotPanel |
| Delivery | Очередь доставки + OrderSlotPanel |

### Предзаказы
- Гость выбирает дату/время
- Калькулятор предоплаты с методом оплаты
- Автоактивация в день заказа при открытии ресторана
- Карточки предзаказов с раскрывающимся составом
- Отмена предзаказа с уведомлением

### Вид официанта
- Только свои столы (назначение официанта к столу)
- Компактная карточная сетка (80px)
- Скрыт sidebar, полноэкранный зал
- Скрыты финансовые данные и кнопки удаления

## Модуль 11 — Электронные документы и подписи (`/admin/documents`, `/shared/sign/[token]`)

### Что сделано
- Таблица шаблонов `company_documents` (заголовок, текст, обязательный/нет)
- Таблица подписей `employee_signatures` (статус, токен, base64 подпись, IP, время)
- Токен генерируется автоматически (encode(gen_random_bytes(32), 'hex'))
- API `/api/admin/documents` — CRUD шаблонов
- API `/api/admin/documents/[id]/sign-link` — генерация/получение ссылки для сотрудника
- API `/api/admin/documents/signatures` — матрица «сотрудник × документ»
- API `/api/admin/documents/my-pending` — авто-создание записей + список неподписанных
- API `/api/sign/[token]` (публичный) — GET получить документ, POST отправить подпись

### Мобильная страница подписания (`/shared/sign/[token]`)
- Тёмная тема, инлайн-стили (без Tailwind)
- Состояния: загрузка → ошибка → уже подписан → активное
- Скролл-гейт: кнопка подписания заблокирована до `Math.ceil(scrollTop + clientHeight) >= scrollHeight`
- HTML5 Canvas с pointer events (работает на пальце и мышью)
- Очистка подписи (кнопка «Очистить»)
- `canvas.toDataURL("image/png")` → сохраняется в БД как base64
- IP-адрес и время фиксируются на сервере

### Защита доступа
- `CheckinGate` показывает сотруднику список неподписанных документов вместо рабочего экрана
- API `/api/admin/shift/checkin` дополнительно проверяет подписи на сервере (двойная защита)
- Ссылки остаются постоянными — сотрудник может открыть и увидеть статус в любое время
- **При изменении текста документа** — все подписи автоматически сбрасываются в `pending`, сотрудники должны подписать заново

### Интерфейс админа
- Вкладка «Документы»: единая форма с выпадающим списком (создание + редактирование)
- При сохранении изменений — модальное подтверждение с предупреждением о сбросе подписей
- Вкладка «Подписи»: коллапсируемый список сотрудников, зелёный/жёлтый статус по каждому документу, кнопка «Скопировать ссылку»

## Ключевые технические решения

### Realtime
- Supabase Channels (`supabase.channel(...)`) для мгновенных обновлений зала
- Подписка на `postgres_changes` для таблиц `orders` и `restaurant_tables`
- Fallback: автообновление каждые 30 секунд на дашборде владельца

### Безопасность
- Все мутации через API (не прямой доступ к Supabase из клиента)
- Service Role Key только на сервере (никогда не попадает в браузер)
- Bcrypt для паролей сотрудников
- IP-адрес фиксируется при подписании документов
- Двойная защита check-in: frontend + backend валидация подписей

### Производительность
- Динамический импорт тяжёлых компонентов (`dynamic(() => import(...), { ssr: false })`)
- Оптимистичные обновления UI (закрытие стола, пометка оплачено)
- Единый fetch + Promise.all для дашборда владельца

### Мобильный UX
- `min-h-screen` → `min-h-[100dvh]` для учёта адресной строки браузера
- `pointer-events` вместо `touch-events` для Canvas подписи (работает везде)
- `pb-20` отступ снизу от хрома браузера на iOS
- Scroll snap на горизонтальных слайдерах
